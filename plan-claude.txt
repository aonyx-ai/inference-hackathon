Remove the Decision Entity

 Context

 The scoping domain has two parallel ways to surface a "the agent needs a human
 to decide" moment:

 1. Artifact.openQuestion + status: "needs-input" — the agent bubbles a
 single question up, the developer answers by chatting with that artifact's
 agent. This is the live mechanism: it's what the planner agents actually
 emit (their raise field), what OrchestrationScreen renders as a "needs
 your input" nudge, and what QuestionBanner shows on the artifact screen.
 2. The Decision entity — a Session.decisions[] array plus
 decision-raised / decision-resolved activity events. This is effectively
 dead: raiseDecision and resolveDecision exist on SessionContext but
 are never called anywhere, and no planner/server code ever creates a
 Decision. It only shows up in fixtures and the diagram.

 We want to delete the second mechanism entirely. The openQuestion path stays
 and fully covers the user-facing behavior, so nothing is lost. (Note: there is
 no database, migration, or Zod schema for decisions — Decision is purely a
 TypeScript type plus React state. Earlier notes in plan.txt that mention a
 libsql decisions table were speculative and do not match this codebase.)

 The planner agents' raise field is not part of this — it feeds
 openQuestion, never created Decision records, and stays as-is.
